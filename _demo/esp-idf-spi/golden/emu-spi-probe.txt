# Golden for the SPI probe ([go] spi ...) of _demo/esp-idf-spi, captured
# from an acceptance run (esp-emu v1.2.0, esp32s31, IDF
# espressif/idf:latest = v6.3-dev, esp-clang toolchain from llgo's cache).
#
# Scope: every [go] spi line the probe prints. The [c]/[INFO]/ROM lines (the
# emulator's own chatter and app_main's reports) are not part of the golden.
#
# Everything in this golden is exact - there is NO floater rule. The probe
# prints no wall-clock values and no addresses; every number is either a
# build fact (the pins, the kHz the driver's clock divider produces, the
# esp_err verdicts, the sentinel codes), or the received-byte shape (below).
#
# The received bytes are the run's one fidelity caveat, and they are exact:
# every rx= line reads ff (all ones). esp-emu DOES complete GPSPI polling
# transactions - the trans-done interrupt fires, so Write/Transfer/WriteRead
# and the CS-pinned session all run the real driver path green end to end -
# but nothing drives MISO on the emulated bus, so the sampled line floats
# high and every received byte is 0xff. On hardware these lines carry the
# actual device answer (e.g. a JEDEC ID in response to 0x9F); verify them on
# the board.
#
# The PASS gate is real end-to-end signal: every binding, glue and driver
# call on the path (bus init with DMA channel allocation, device add, the
# clock-divider math echoed back as 10000/20000 kHz, polling transactions
# through DMA, the bus-acquire lock, the CS-pinned keep-active session with
# its zero-phase CS drop, remove/free) returned esp_err 0; the refusal
# lines pin the binding's honest error surface (0x7101/0x7102/0x7103
# sentinels and the driver's own 0x103). The link from Go, through the
# glue, through the IDF driver, to the (slave-less) bus is exercised and
# green; reading real data needs a device on the bus, which is an
# environment property, not a binding property.
#
# Regression check (the console is a USB-Serial/JTAG stream, so its lines end
# in CR/LF: strip the CR before comparing):
#   grep -E '^\[go\] spi' <emu log> | tr -d '\r' \
#     | diff - <this file, comments excluded>
# A diff means the probe's surface behavior changed. The golden only grows by
# appending rounds (e.g. hardware runs with real device answers), never by
# editing an existing line.
