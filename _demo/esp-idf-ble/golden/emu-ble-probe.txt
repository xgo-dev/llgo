# Golden for the BLE central + GATT client probe ([go] ble ...) of
# _demo/esp-idf-ble, captured from an acceptance run (esp-emu v1.2.0, esp32s31,
# 16 MiB PSRAM, host peer idfproj/host/bumble_peer.py on 127.0.0.1:9544).
#
# Scope: every [go] ble line the probe prints. The [c] lines (the glue's own
# address/free-heap report and the heap marks) are not part of the golden: the
# heap byte counts legitimately vary between runs, and the "own address" line
# reports the address the host-side Bumble controller presents.
#
# Floater rule. Everything a `*` replaces is a value that comes from the peer
# script, from the controller, or from the peer's attribute table, not from the
# firmware under test:
#
#   addr=, addrtype=, rssi=   the host peer's advertised address, its type
#                             (1 = random static) and the RSSI the Bumble link
#                             synthesizes (-50)
#   conn=                     the ConnID: the controller's connection handle (1
#                             for the first connection on a Bumble LocalLink)
#                             packed with this package's generation counter,
#                             i.e. (generation << 16) | handle
#   reason=                   the HCI disconnection reason the peer caused (531
#                             = 0x213, a peer-initiated disconnect tagged with
#                             NimBLE's HCI base)
#   mtu=                      the ATT MTU the exchange negotiated: min of the
#                             firmware's preferred 256 and the peer's 517
#   count=, chrs=             how many services the peer's attribute table has
#                             (Bumble's GAP and GATT services plus the two the
#                             script adds) and how many characteristics each
#                             discovered service carries
#   uuid=, handle=, end=,     the peer script's UUIDs and its attribute
#   props=                    handles/property bits, which follow from the order
#                             the script registers its services in
#   read len=                 the echo characteristic's initial value, which is
#                             empty in the peer script
#
# Everything else is exact, and each of those values was produced by the
# firmware:
#
#   op=                       the probe's own monotonic operation counter, fixed
#                             by the phase order (scan 1, cancelled scan 1 ->
#                             second scan 2, StopScan burns 3, Connect 4)
#   advlen=11                 the peer's 9-byte name plus its AD header
#   read=1 write=1 notify=0   Characteristic.CanRead/CanWrite/CanNotify applied
#                             to the discovered property bits
#   mode=1, mode=2            the ATT write procedure Write selected from those
#                             properties (1 = write request, acknowledged); a
#                             with-response write can only complete through the
#                             peer's ATT Write Response. mode=2 is the ATT write
#                             command WriteWithoutResponse asked for explicitly,
#                             which the read-back proves the peer applied
#   data=ping-0x, u128        exactly the bytes the probe wrote: the echo
#                             characteristic stores them and the peer pushes the
#                             same bytes back as a notification, so both the
#                             read-back and the notification payload are
#                             firmware input returning to the firmware
#   n=1, n=2 / ind=0          notification order and "a notification, not an
#                             indication"
#
# Regression check (the console is a USB-Serial/JTAG stream, so its lines end in
# CR/LF: strip the CR before comparing):
#   grep -E '^\[go\] ble' <emu log> | tr -d '\r' | sed -E \
#     -e 's/(addr|addrtype|rssi|conn|reason|mtu)=[^ ]+/\1=*/g' \
#     -e 's/(count|chrs|handle|uuid|props|end)=[^ ]+/\1=*/g' \
#     -e 's/(read len)=[0-9]+/\1=*/' \
#     | diff - <this file, comments excluded>
# A diff means the central's behavior changed: the golden only grows by
# appending a phase, never by editing an existing line.
