# idfproj/host/apclient).
#
# Scope: every [go] ap line except the heap marks ([go] ap heap ... carries
# IDF-heap byte counts that move by a few dozen bytes between runs) and the
# one informational count documented below. Everything else is byte-stable
# across runs: five recorded runs differ only in the heap-mark arithmetic.
# The station MAC and both addresses are part of the golden because the
# emulator's station and the firmware's netif are deterministic
# (02:e5:00:00:00:02, AP 192.168.4.1, first lease 192.168.4.2).
#
# "stations on start n = 1" is the one timing-dependent line: the emulator
# joins as soon as it sees the beacons, so an earlier or later boot can report
# 0 there. Treat 0 or 1 as a pass; the gated shape is the later, post-association
# list.
#
# The comparison is automated: run-acceptance.sh normalizes exactly four values
# before diffing (the initial station count, "aid = N", "rssi = N", "reason = N"),
# so those may differ freely and everything else must match byte for byte.
# Discipline: lines may only be APPENDED at the end of a section, and an
# existing line changes only when the probe's contract changes.
